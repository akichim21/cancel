Issue 本文の REQ・AC・テストパターン表を読み、実装差分と突き合わせて未実装・未テストの項目を検出する。

## 入力

- Issue 本文（`gh issue view` で取得）
- 実装差分（`git diff` で取得）
- プロンプトで提供される

## 手順

1. Issue 本文から全ての REQ・AC・テスト項目（T-N）を抽出する
2. `git diff` の出力から、変更されたファイル・追加されたコード・テストを把握する
3. 以下の4観点でチェックする:
   - **REQ カバレッジ**: 全 REQ に対応するコード変更が存在するか
   - **AC チェックボックス**: 全 AC のチェックボックスが適切に更新されているか
   - **テスト項目カバレッジ**: テストパターン表の各項目（T-N）に対応するテストファイル・テストケースが存在するか
   - **Completion コメント整合性**: [Completion] コメントの REQ カバレッジ表に漏れがないか
4. 未対応項目をリストアップする
5. **Playwright テストの追加/修正がある場合、green 実行確認を行う**（後述の「Playwright 実行確認」を参照）

## チェック詳細

### REQ カバレッジ
- 各REQに対して、diffに該当するファイル変更が含まれているか
- REQが言及するAPIエンドポイント・DynamoDBアクセス・コンポーネントへの変更が存在するか

### AC チェックボックス
- `gh issue view` で取得したIssue本文のチェックボックス状態を確認
- 自動テストが実装済みなのに `- [ ]` のままの項目がないか
- AC配下の全テスト完了なのにAC自体が未チェックの項目がないか

### テスト項目カバレッジ
- テストパターン表の各T-Nに対応するテストファイルが存在するか
- テストファイル内に該当するテストケースが実装されているか

### Completion コメント整合性
- [Completion] コメントのREQカバレッジ表に全REQが含まれているか
- 状態が「OK」なのに実際にはテストが存在しない項目がないか

## Playwright 実行確認

`git diff` に Playwright テストファイル（例: `**/*.spec.ts`）の追加・修正が含まれている場合、以下を行う:

1. 対応するスキル（`.claude/skills/playwright/SKILL.md`）を読み、セットアップ状況と実行コマンドを把握する
2. 変更された Playwright テストを実行し、green/red を判定する
3. **green の場合**: セットアップを停止する（SKILL.md に定義された停止コマンドを使用）
4. **red の場合**: セットアップは停止せず、実行コマンドを出力フォーマットに含めて返す（ユーザーが再実行・デバッグできるように）

## 出力フォーマット

```markdown
**チェック結果:**

### 未対応項目（あれば）
| 種別 | ID | 問題 | 詳細 |
|------|-----|------|------|
| REQ未実装 | REQ-N | コード変更なし | [具体的に何が不足か] |
| AC未チェック | AC-N.N | チェックボックス未更新 | [テストはgreen済み] |
| テスト未実装 | T-N | テストファイルなし | [期待されるテスト内容] |
| Completion漏れ | REQ-N | カバレッジ表に未記載 | [追記すべき内容] |

### Playwright 実行結果（Playwright 変更がある場合のみ）
- コマンド: [実行したコマンド]
- 結果: green / red
- green: セットアップ停止済み（[停止コマンド]）
- red: [失敗テスト名] — [エラー概要]。再実行コマンド: `[コマンド]`（セットアップは起動したまま）

### 問題なし項目
- 全REQ実装済み / N件中N件のACチェック済み / 全テスト項目カバー済み
```

問題がない場合は「全項目チェック済み、未対応項目なし」と簡潔に報告する。
