# PR タイトル・本文テンプレート

## タイトル

- Conventional Commits 風プレフィックス: `feat:` / `fix:` / `refactor:` / `docs:` / `test:` / `chore:` / `perf:` / `style:`
- 70 文字以内
- 動詞は現在形・命令形
- 末尾にピリオドを付けない
- ブランチ名と概要が一致すること

例:

- `feat: 顧客一覧にステータスフィルタを追加`
- `fix: 予約キャンセル時の決済戻し抜けを修正`
- `refactor: BookingService の例外ハンドリングを統一`

## 本文テンプレート

```markdown
## Summary
- <変更の要点を 1-3 行の箇条書きで>
- <"なぜ" を含める。"何を" は diff から読める>

## Changes
- <主要な変更点をファイル / モジュール単位で>
- <挙動が変わるユーザー導線があれば明記>

## Test
- [x] <自動テストの種類と対象> 例: jest: `src/__tests__/cancellations.test.js` green
- [x] <Playwright があれば対象フロー>
- [ ] <人力で確認が必要な項目があれば未チェックで残す>

## Notes
- <レビュアー向けの注目点・トレードオフ・既知の制約>
- <ロールアウト時の注意（マイグレーション、フィーチャーフラグなど）>
```

セクションの扱い:

- `Summary` / `Changes` / `Test` は必須
- `Notes` は書くことがなければセクションごと削除して良い
- UI 変更がある場合のみ `## Screenshots` を追加し、画像 / 動画リンクを貼る

## 含めない内容

- クロスリポジトリな Issue 参照（`Closes #N` / 外部メタトラッカへの URL など）
- 機密情報（API キー、内部 URL、個人情報、内部チャンネル名など）
- 同一ブランチに含まれない将来の変更計画
