# サロンボード取り込み（業務フロー）

サロンが利用する予約管理「サロンボード」（ホットペッパービューティーの管理画面）から、キャンセルされた
予約を自動で取り込み、当サービスのキャンセル請求を自動作成する機能（GTSS-817）。現状の人手登録を、
毎日の自動取り込みに置き換え、取りこぼし・入力負荷・入力ミスをなくす。

認証情報（ログインID・パスワード）は当面**会社（アカウント）単位**で管理する。会社ログインで取得できる
「ヘアサロン」一覧を取り込み、各店舗のキャンセルをまとめて取得する（店舗単位の認証情報管理・サロンボード
以外の連携先は将来の拡張）。

## 連携の初期設定（運営）

1. 管理画面で対象アカウント（会社）を開き「サロンボード連携設定」でログインID・パスワードを入力。
2. システムが実際にサロンボードへログインし、その会社の**「ヘアサロン」一覧（店舗名・サロンID）**を取得。
   - サロンボードのトップには「キレイサロン」等の区分も並ぶが、**取り込み対象は「ヘアサロン」区分に限定**。
     店舗名では判別せず区分で抽出する。
3. 取得した店舗一覧を**確認画面**に表示。運営は各店舗の**表示名（店舗名）を編集**できる。
4. 確認して保存すると、店舗一覧・認証情報（暗号化）・連携済みステータスをまとめて保存。
- ログイン失敗 / ヘアサロン 0 件のときはエラー文言を表示し、認証情報・店舗一覧は保存しない。
- パスワードは秘匿情報として安全に保管し、画面上では平文で再表示しない（マスク）。

## 自動取り込み（日次）

- 毎日 **午前0時10分（日本時間）** に自動実行（手動実行ボタンでも同一処理を即時起動できる）。
- 連携済み会社の全ヘアサロンを店舗ごとに処理。ある店舗・ある予約の失敗が他を止めない（失敗は件数計上）。
- 抽出条件（来店予定日基準）:
  - 来店予定日が「実行日の3日前」〜「実行日の3か月後」
  - 来店予定日が**契約日（＝当サービスへの申請作成日）より後**（日本時間の日付で比較・同日含まず）
- 取り込み対象: ステータスが**「お客様キャンセル」「無断キャンセル」**かつ**支払い種別が「現地支払い」**。
  - うち**予約時キャンセル規定（キャンセル料率）が設定されている**予約のみキャンセル請求を作成。
- 取り込み済み（同一店舗・同一予約ID）は再作成しない。確定理由でスキップした予約は再評価しない
  （詳細取得失敗のみ翌日リトライ）。

### キャンセル料の算出

「予約時キャンセル規定」（料率）を、来店日時・キャンセル日・キャンセル種別（お客様／無断）に当てはめて算出する。
- 無断キャンセルは無断料率、お客様キャンセルは来店日とキャンセル日の関係（当日／N日前）に応じた料率。
- 請求金額（税込）＝ 予約金額（税込）× 料率、円未満切り捨て、上限は予約金額。
- サロンボードの「キャンセル料」表示欄（「キャンセル料なし」「-」等）は信頼できないため判定・算出に使わない。

## 「送信前」での作成 → 確認 → 送信

- 取り込みで作成したキャンセル請求は**「送信前」ステータス**で一覧に保存し、**取り込み時点では顧客へ
  決済リンク通知（メール／SMS）を送らない**。
- 運営担当者（またはサロン本人）がキャンセル一覧の**「送信」ボタン**から内容を確認・調整して顧客へ送信する。
  - モーダルで金額・キャンセル日・来店日時・**キャンセル料（編集可能）**・送信先を表示。
  - キャンセル料は **0 より大きく予約金額以下**でなければ送信できない。
  - 送信先はメールがあればメール、無ければ SMS（メール・電話が両方無い予約はそもそも取り込み対象外）。
  - 「送信」で決済リンク通知を送り、ステータスを**請求中（送信済み）**へ遷移。
- **二重送信防止**: 「送信前」のときのみ送信を受け付け、二重押下・リトライがあっても決済リンク発行・通知が重複しない。
- 送信は**管理画面（運営）とサロン向けポータル（サロン本人）の両方**から可能。サロン本人は自社配下のみ送信できる。

## 取り込み対象外・スキップの記録

次は請求を作成せず**取り込みログ（監査ログ）**に記録し、管理画面で後から確認できる:
- 支払い種別が「現地支払い」以外（対象外）
- 予約時キャンセル規定の記述なし（スキップ）
- 予約詳細の取得に失敗（スキップ・翌日リトライ）
- メール・電話が両方とも取得できない（送信不能のため対象外）
- 料率が解釈不能（スキップ）

取り込みログは予約（店舗単位の予約ID）ごとに 1 件（重複行を作らない）。顧客 PII を含み得るため、保持期限・
退会（申請削除）時のマスク対象・閲覧権限は既存の顧客 PII マスク方針（`application-flow.md`）に揃える。

## 非本番環境の PII 取り扱い

本番以外（dev / local / test）では、取り込んだ顧客の個人情報（氏名・カナ・電話・メール）を保存前にマスク／
差し替える。氏名・カナはダミー、メール・電話は紐づく申請（サロン本人）の連絡先をセットする（実顧客へ誤送信せず、
dev で実配信テストができる）。予約ID・金額・日時等の業務データはそのまま保持する。

## 一覧の表示項目

管理画面・サロン向けポータルの両方で、請求ステータス・**店舗名（会社名とは別に発生店舗名）**・予約ID・
予約ステータス・支払い種別・予約金額・キャンセル料請求額・来店日時・キャンセル処理日・担当者・お客様名・
お客様電話番号・操作ボタン（「送信前」は送信ボタン）を表示。詳細画面で予約時キャンセル規定・受信日時・メニュー名等も確認できる。
